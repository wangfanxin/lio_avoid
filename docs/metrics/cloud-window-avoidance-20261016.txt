GIVING EGO'S MAP THE MEMORY IT ASSUMES IT HAS: one flag in our own relay, and the crossing stops going
through pillars
2026-10-16   HEAD 3c48eef + the change below.  Runs: `logs/missionA-DIAG8-map-slice` (window 0),
             `logs/missionA-DIAG9-window3` (window 3.0 s).  Same world, same planner, same parameters.

=== THE DEFECT THIS FIXES, IN ONE SENTENCE ====================================================
ego's occupancy map is rebuilt from the CURRENT cloud message alone -- `cloudCallback` resets its local box
(`grid_map.cpp:835`) and then writes `occupancy_buffer_inflate_[idx] = 1` per accepted point (`:910`), with no
ESDF, no ray-casting and no probability update anywhere in that variant -- so an obstacle exists in it only
while the current scan sees it, and MEASURED on the diagonal crossing the map held **0 % of the pillar the
vehicle was inside** while holding 31-39 cells of pillars 1.1-1.6 m away
(`docs/metrics/diagonal-map-truth-20261016.txt`).

=== THE FIX, AND WHY IT BELONGS IN OUR CODE ===================================================
A pillar that is unmarked at 0.4 m WAS marked at 1.0-1.5 m a second or two earlier.  The measured closing speed
on this mission is ~0.4 m/s, so the whole approach the map forgets spans about 3 s.  `src/planner/cloud_relay.py`
therefore gains `--window SECONDS` (default 0.0 = exactly the old behaviour): the decimated scans of the last N
seconds are unioned by voxel key before publication.  It is valid because this cloud is in the WORLD frame --
in a static world the union of consecutive scans is the swept view, not a smear -- and it costs nothing in
precision: the union is keyed on the same 0.10 m lattice the map stores.

The alternative was to patch ego's map to accumulate.  Not done: the map is a third-party component whose
behaviour every earlier measurement in this project describes, and the relay is ours.  `EGO_CLOUD_WINDOW` is
the harness knob; the relay's own selftest gained five checks (a static scene must NOT grow, a voxel inside the
span must survive, one outside must not, window 0 must equal one scan, a shared voxel must not duplicate).

an obstacle seen from an earlier viewpoint stays in the map through the moment the current scan is occluded.

=== WHAT IS NOT CLAIMED =======================================================================
  * **C2 still FAILS**: 2108 samples lie between +0.150 and +0.200 m of a surface, i.e. the vehicle now clears
    the pillars but not by the 0.20 m the row asks for.  This is a real remaining gap, not a rounding.
  * The near band is still not perfect: at 0.42 m, pillar #11 still reads 0 cells in one slice.  A 3 s window
    spans the approach, not the contact itself; the map still cannot represent a surface it is touching.
  * **One A/B is not a distribution.**  Every ego crossing before this one failed C2, and the individual
    crossings varied a lot (-0.071 to -0.279 m), so this needs reproducing before the window is promoted to a
    default.  `EGO_CLOUD_WINDOW` defaults to 0.0 in the harness precisely so that it can be.
  * The mechanism by which a surface within ~0.5 m vanishes from the MAP is still not separately established
    (three candidates in `diagonal-map-truth-20261016.txt`); this round shows the window is sufficient, not
    that any particular one of them is the cause.

=== REPRODUCTION, ADDED AFTER THE RUN, AND IT IS NOT AS CLEAN AS THE FIRST (DIAG10) =============
The paragraph above said "one A/B is not a distribution", so the same flag was flown again on the same mission
(`logs/missionA-DIAG10-window3-repro`, `EGO_CLOUD_WINDOW=3.0`, HEAD b634876):

    samples inside a pillar               2056            0               0
    the C2 row's own count                5356/48943      2108/53753      8985/58963
    sortie                                rc=0            rc=0            rc=0, no hang

WHAT REPRODUCES: **no penetration** -- 0 samples inside a pillar surface, twice out of two -- against **six of
six** ego crossings at window 0 that all penetrated (DIAG2 -0.279, DIAG3 -0.169, DIAG4 -0.071, DIAG5 -0.277,
DIAG6 -0.129, DIAG8 -0.164 m; the rectangle control DIAG1 -0.299 m is a different planner and is not counted).

WHAT DOES NOT: the MARGIN.  +0.150 m in DIAG9 against +0.056 m here, and the C2 count is four times larger.
The honest statement is therefore "the window removes the penetration and leaves a clearance that varies by
about 0.1 m between runs", not "the window gives 0.15 m".  One visible difference between the two runs points at
where that variance lives: DIAG10's own tracking was worse throughout (A4-v the FCU's EKF 48.70 mm/s against
29.82, the velocity it was fed 136.46 against 83.92, and B1's box 2.947/3.121 against 3.097/3.024), so part of
the margin difference is the vehicle flying the same plan less tightly, not the planner choosing worse.

So C2 remains FAILED in every ego crossing so far, and the next lever is no longer the map: it is the margin the
plan itself keeps, now that the map can hold the obstacle through the approach.

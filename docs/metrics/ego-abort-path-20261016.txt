=== THE BENCH =================================================================================
`_stage/ego-kill-plan.sh`, which is `_stage/f2-kill-bench.sh`'s (`RECT25-kill-plan`) method moved to this
planner: the diagonal is flown with `PLANNER=ego` and `EGO_CLOUD_WINDOW=3.0`, the script waits for the
supervisor to say the plan box is talking, waits 8 s more, and then kills it.  NOTHING IS KILLED BY NAME: the
PID is the unique `pgrep -f 'planner/ego_source.py'` match, the whole matched command line is printed to the log
before anything is touched, and the count must be exactly 1 or the script refuses.  The only injected fault is
the silence.

=== AND THE RULE HOLDS IN BOTH DIRECTIONS, ON THE SAME STACK ===================================
Criterion 4 asks that "the stream keeps talking after COMPLETED" not be broken.  A single abort proves nothing
on its own -- a supervisor that aborts on every finished tour would produce the same log.  So the other
direction is read off the two runs that COMPLETED the tour:

    run                    phases as flown                          abort?   bridge's final plan_age
    DIAG9-window3          preflight takeoff hold leg1 leg2 land done  NONE   0.00 s  (still talking)
    DIAG10-window3-repro   preflight takeoff hold leg1 leg2 land done  NONE   0.00 s  (still talking)
    DIAG11-kill-plan-ego   preflight takeoff hold leg1 ABORT land done NAMED  8.20 s  (silent)

`plan_age` in the bridge's shutdown line is the age of the last `/plan/cmd` message when the sortie ended: 0.00 s
means the plan box was still publishing at the end, 8.20 s means the stream had gone quiet.  Both completed runs
also end with the adapter's own line -- `TOUR COMPLETE -- the stream now carries trajectory_flag = COMPLETED and
KEEPS TALKING (it does not stop asking for more)` -- and neither produced an `abort` phase.  **A finished tour
and a dead box are different facts, and the supervisor tells them apart exactly as the F2 design requires.**

=== AN INSTRUMENT NOTE, FOUND BY GETTING IT WRONG =============================================
The first version of this round's figure marked the kill point as "the last `/plan/cmd` row", and it landed on
the final truth sample with the vehicle already on the ground.  Two separate reasons, both worth recording:
  * the trajectory recorder writes ONE FINAL ROW at shutdown, 4.580 s after the last real command (measured),
    so "the last row" is not "the last message";
  * **the two recorders do not share a clock**: `tap.csv`'s `t_us` runs 34153..54904696 (boot-relative) while
    `traj.csv`'s runs 1792082181016465..1792082211736758 (epoch).  Matching them by timestamp is meaningless.
The figure now places the kill by TIME-FROM-THE-END (both recorders are stopped together by the harness), which
is honest about what is actually known.  No earlier measurement is affected: every cross-analysis in this
project matches truth to plan by POSITION or by the world file, never by comparing those two clocks.

=== WHAT IS NOT CLAIMED =======================================================================
  * The touchdown was FIRM: the FCU reports `SIM Hit ground at 0.639375 m/s`.  It is a landing and a disarm,
    not a gentle one, and the abort happened during `leg1` at 0.88 m altitude -- the lowest and shortest abort
    this mission can produce, not a worst case.
  * The abort is on the DIAGONAL mission.  Mission A's five-waypoint route has not been aborted mid-flight;
    the supervisor's gates do not depend on the mission, but that is an argument, not a measurement.
  * The plan box was killed with SIGKILL, which is the harshest form of silence.  A box that is alive but
    wedged (the `--stall-topic` case, which the FSM tooling can produce) is a different shape of the same gate
    and is not exercised here.

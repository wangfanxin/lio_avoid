PLAN X: THE TOUR OWNED BY EGO'S OWN SEQUENCER  (2026-10-16, parked bench, no flight)

WHY.  Under Route B the tour is split three ways: `ego_contract_shim.py` sends one goal at a time on
`/move_base_simple/goal`, decides arrival itself (0.30 m + 5 s dwell) and stamps `trajectory_id` / COMPLETED;
ego's FSM is dragged along by those goals; `traj_server` samples whatever spline arrives.  Upstream ego does
all of that INSIDE one process, and the mission-B review's summary (section 7) is exactly about that split.
Plan X restores the upstream arrangement: `flight_type 2` (PRESET_TARGET) + PATCH 0008's waypoint sequencer
makes EGO own the tour, and the shell shrinks to the two things the contract still needs -- an id per waypoint
and a real COMPLETED.

WHAT WAS BUILT THIS ROUND (all of it no-flight)
  1. `src/planner/ego_contract_shim.py` gains `--tour-source {shell,ego}` (default `shell` -- the flown
     behaviour is untouched).  Under `ego`:
       * no goal is ever sent (`goal_to_send()` returns None): a goal addressed to a FSM that is not
         subscribed to `/move_base_simple/goal` would have no reader;
       * the shell's own arrival gate is INERT (`_sequence()` returns immediately) -- nothing but ego's index
         may advance the tour;
       * `/wp_index` (`std_msgs/Int32`, PATCH 0011: the current waypoint, `-1` when finished) drives
         `trajectory_id = wp_index + 1` and the COMPLETED transition, and a BACKWARDS index is followed rather
         than hidden, because a wrong index is a fact about ego that the trace should show;
       * the post-COMPLETED HOLD (round 81's fix) is unchanged: the point is pinned to the last waypoint with
         v = a = 0 and a latched yaw.
     `--selftest` asserts the mode's own contract: no goal in 30 ticks, the shell's gate inert while the
     vehicle sits exactly on target 1 for 15 s, ids following 1 -> 2 -> 1 (backwards) -> 3, `-1` producing
     COMPLETED with the hold on the last waypoint, and the wp_index counter.
  2. `src/planner/ego_on_lio.launch.py` gains the arguments the PRESET path needs to be selectable at all:
     `flight_type` (default 1 = the flown baseline), `waypoints` (`"x,y,z;x,y,z"`, parsed inside an
     `OpaqueFunction` because a launch argument's value is only known at execution), `waypoint_start_alt`,
     `waypoint_advance_m`, `waypoint_loop`.  A malformed list raises instead of flying a shorter tour.
  3. `_stage/s13-planx.sh` is the bench: the same parked stack as `s12-rig.sh` (SITL, lidar, LIO, bridge,
     relay, ego, traj_server, a scripted pose walking pad -> W1 -> W2 -> stay) with the three differences that
     ARE the experiment -- `flight_type:=2`, `waypoint_start_alt:=1.28`, `--tour-source ego`.  The tour's
     waypoints are generated by the shell's own `_targets_from_world` (`_stage/planx-waypoints.py`) rather
     than typed, because a hand-passed list in the wrong frame cost a whole bench run on the previous round.

WHAT IT MEASURES, and what would count as failure
  * EGO'S OWN SEQUENCER advanced: `WP-INDEX` lines moving 0 -> 1 and then `-1` (finished), plus the FSM's
    `TOUR-ADVANCE` / advance transitions.  Failure = the index never leaves 0, which would mean the advance
    rule (`plan_done && wp_d_veh < waypoint_advance_m`) never fired with the scripted pose.
  * THE CONTRACT followed ego: `trajectory_id` taking the values 1 then 2 in `shim_trace.csv`, and COMPLETED
    arriving from ego's `-1` rather than from the shell's arrival gate.  Failure = an id that never moves, or
    a COMPLETED that arrives while ego still says 0 -- either would mean the shell is still the owner.
  * `traj_server`'s new telemetry fires and its invalid-time branch never does.
  * The planner's own health counters, so this run can be compared with the MANUAL arm's later.

2. THE CONTROL ARM, AND THE BUG IT CAUGHT (runs 17:39 and 17:42 -> 17:44)
   The first control arm planned NOTHING: `INIT -> WAIT_TARGET` and no `Triggered!` line at all, zero splines,
   zero forwarded messages.  Two candidate explanations (the FSM never got a goal / the shell never sent one)
   were indistinguishable from the logs, so the shell was given a line per goal send (`shim: goal i/n -> ...`)
   plus `sys.stdout.reconfigure(line_buffering=True)` -- and the very next run printed the answer:

       AttributeError: 'Namespace' object has no attribute 'goal_resend_s'
       (ego_contract_shim.py, in main(), at the P3-2 start-up banner)

   **THE SHELL WAS CRASHING AT START-UP IN THE FLOWN MODE.**  The P3-2 banner added earlier the same day (for
   the review's observability item) referenced `args.goal_resend_s`, which is not an argument -- the sequencer
   owns that value -- while `--selftest` passed, because the selftest never built the banner.  The fix is not
   just the missing attribute: the banner is now two functions taking plain floats
   (`_print_p3_2_banner`, `_print_tour_source_banner`), the parser is one function (`_parser()`), and

   BANNERS -- the coverage whose absence made this possible.  Re-measured after the fix (17:44): the control
   arm completes the tour again.

CORRECTION AND RESULT, SAME DAY: THE ROUND-1 CONCLUSION ("PLAN X DOES NOT ADVANCE") WAS THE INSTRUMENT

WHAT WAS WRONG.  The Plan X arm of the first bench run reported 526 `GEN_NEW_TRAJ -> GEN_NEW_TRAJ` and no
advance, and it was recorded as "arming works, advance does not".  The ego log said more than the summary did:
the failures were `PLANNER-STALL: local replan failed ...` escalating to global replans, and the optimiser
itself was printing

    [rebound_optimize]: Solver error. Return = -1008, A rounding error occurred; alternatively,
    no line-search step satisfies the sufficient decrease and curvature condition

-- a CERES failure in the local B-spline, i.e. the state being planned FROM was moving in a way the planner
could not follow.  It was: `_stage/s12-fake-odom.py` TELEPORTED.  It held at stop k, then held at stop k+1, so
consecutive messages carried a **5.65 m jump with a twist of exactly zero** -- an infinite speed reported as
standing still.  In the MANUAL arm the shell's 1 Hz goal resend re-anchors `planGlobalTraj` from the new
odometry every second, which HIDES that completely; Plan X has no resend by design, so the same pose model
broke it.  **Nothing in the first run distinguished "Plan X is broken" from "the pose is a step function", and
the round-1 record named the first as the finding.**

THE INSTRUMENT, FIXED (`_stage/s12-fake-odom.py --speed`, default 1.0 m/s).  The itinerary is now a timeline of
hold and travel legs; the pose moves at a finite speed and the twist published is the one that moves it (zero
during a hold, which is what the FSM's own `> 0.1 m/s` gate expects to see in transit and NOT at a stop).
`--speed 0` restores the old teleport exactly, so every earlier run stays reproducible.  Both arms were then
re-run BACK TO BACK on the same instrument (`_stage/planx-ab.sh`, dirs `planx-bench-20261016_174846` (control),
`..._175001` (Plan X)).

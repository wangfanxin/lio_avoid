=== WHY THIS WAS THE NEXT STEP ================================================================
The corrected census left a hard cut at L_x = -2.5 in what ego's map keeps, and exactly one candidate
in the map's own code makes a hard cut in one axis: grid_map.cpp:851-855 accepts a cloud point only
when it lies within grid_map/local_update_range OF THE VEHICLE, per axis.  A cut at -2.5 with the
vehicle parked at the L origin needs EITHER a band of half-width 2.5 (no offset) OR a band of 5.5
offset by camera_pos_.x = +3.0.  Only the node can say which.

=== SO THE LEADING HYPOTHESIS IS ELIMINATED ===================================================
   The band's own edge is NOT the cut.  For a 5.5 m band to cut at -2.5, the map's own position would
   have to be camera_pos_.x = +3.0 -- and there is no evidence of that: the map reads grid_map/odom,
   which this run confirms has exactly ONE subscriber (the node), and the topic it is remapped to,
   /lio/robo/odom, is the stream the acceptance table measures against truth at 3-6 mm (A1).
   A 3-metre error in it would be impossible to miss.
   AND the parameter is not misconfigured: 5.5 is what the launch file sets.  So this round removes a
   candidate rather than adding one, which is worth as much -- it was the only mechanism in that file
   that could cut in a single axis.
